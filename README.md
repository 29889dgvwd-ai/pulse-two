# PULSE TWO ✳ — приложение для двоих

Оригинальный адаптивный веб-прототип для пары или двух близких людей. Вдохновение: отдельное пространство с входом по коду, но акцент на **игры и маленькие совместные действия**, а не повторение функций Togetherly.

## PULSE TWO 2.0 — новые возможности

- **Колесо моментов:** общий генератор случайных занятий с синхронизацией на обоих экранах.
- **Тайный вопрос:** оба отправляют ответы, и только после второго ответа открывается результат. До этого сервер не отправляет чужой текст ни одному клиенту.
- **Рисуем вдвоём:** сенсорный холст, сохранение линий в комнате, четыре цвета и отмена собственной линии.
- **Вкладка «Вместе»** в мобильном и десктопном меню, промо-карточки функций на главной.

## Что реализовано

- **12 синхронных игр**: крестики-нолики, четыре в ряд, камень-ножницы-бумага, один вайб?, мемори, рефлекс, цепочка слов, число-секрет, эмодзи-загадки, блиц-квиз, история на двоих и расшифруй слово.
- **Живые комнаты на двоих** с восьмизначным кодом и ссылкой-приглашением.
- **Голосовой чат** на WebRTC со входящим вызовом, принятием и выключением микрофона. При переходах между разделами звонок не сбрасывается.
- **Мини-чат** со сжатыми сообщениями в пределах пары.
- **Чек-листы на двоих**: каждый отмечает собственную галочку, общая полоска прогресса растёт после двух отметок. Можно добавлять и удалять пункты.
- **Сигналы «Привет», «Дай пять», «Поддержка»**. На поддерживаемых браузерах — вибрация, в других — визуальное уведомление/короткий звук.
- **PWA** (установка веб-приложения на домашний экран) и мобильная адаптация.
- **Исходники Expo-обёртки** в `mobile/`: нативная тактильная отдача iPhone через `expo-haptics` при открытом приложении.

## 📲 Публикация для двух телефонов — одна общая ссылка

Разверни этот **Node.js Web Service** на Render, который даёт бесплатный HTTPS-адрес `https://ИМЯ.onrender.com` и поддерживает WebSocket. **GitHub Pages здесь не подходит**, потому что игры и голос используют сервер.

1. Опубликуй файлы проекта в отдельном GitHub-репозитории `29889dgvwd-ai/pulse-two` (нужно разрешить GitHub ChatGPT Connector запись именно в `pulse-two`).
2. Нажми **[Развернуть PULSE TWO на Render](https://render.com/deploy?repo=https://github.com/29889dgvwd-ai/pulse-two)**. Конфигурация `render.yaml` уже подготовлена: бесплатный сервис Node.js, авто-проверка `/health`.
3. После успешного развёртывания открой свой HTTPS-адрес Render, нажми «Создать комнату» и **скопируй ссылку-приглашение** прямо из приложения. Другой человек открывает её, пишет имя и нажимает «Войти» — вы в одной комнате.

**Ограничения бесплатного Render:** после ~15 минут простоя сервис засыпает; при перезапуске данные в локальном `data/rooms.json` стираются. Для долгосрочного хранения потребуется внешняя БД или платный постоянный диск. **Голос** (WebRTC) на некоторых мобильных сетях может потребовать TURN-сервер. Сигналы в Safari на iPhone визуальные — физической вибрации браузер не даёт.

## Запуск за 1 минуту

Установи Node.js 18+.

```bash
cd PulseTwo
npm start
```

Открой **http://localhost:3000** — откроется вход, там можно создать комнату. Для двух вкладок с *разными участниками* используй разные браузерные профили или два браузера: идентификатор сохраняется в localStorage.

**Внешних npm-зависимостей нет**: сервер WebSocket включён в проект.

### Как играть с двух телефонов

Для удалённого подключения сайт нужно развернуть на сервере с **HTTPS**, поддержкой **WebSocket Upgrade** и запущенным Node.js-процессом (например, на Node-хостинге). Статический GitHub Pages **не подходит**, потому что комнаты, игры, сообщения и сигнализация звонка требуют сервер.

На сервере задаётся `PORT` автоматически хостингом либо вручную: `PORT=3000 npm start`. Проксируй HTTPS и WSS к Node-приложению. Для надёжных звонков через разные сотовые сети может понадобиться собственный **TURN-сервер** (здесь указаны только STUN-серверы).

Вставь партнёру ссылку с `?room=КОД` или сам код. Два участника входят в одну комнату.

## iPhone и вибрация

Обычный Safari не поддерживает Web Vibration API, поэтому **в веб-версии на iPhone физическую вибрацию обещать нельзя**. Файлы в `mobile/` дают путь к настоящей тактильной отдаче через Expo при открытом мобильном приложении (понадобится публикация сайта по HTTPS и сборка мобильного приложения). Это не фоновые push-уведомления.

## Текущие ограничения прототипа

- Данные комнат, чек-листов и сообщений сохраняются локально в **`data/rooms.json`** и переживают перезапуск Node.js при сохранности диска. Если на хостинге временная файловая система, данные могут исчезать при пересборке или перезапуске контейнера. Неактивные комнаты удаляются через 30 дней.
- Нет регистрации и проверенных аккаунтов, сквозного шифрования сообщений, политики приватности и внешней базы данных. Код комнаты — единственный ключ; **не отправляйте чувствительные данные**.
- Здесь есть красивые **виджеты внутри приложения**, а не нативные системные виджеты на рабочем столе iOS/Android.
- Когда приложение закрыто, сигнал не вызывает фоновое уведомление. Для этого потребуются Push/FCM/APNs.
- Голос использует прямое соединение WebRTC. Некоторые сети блокируют его без TURN.
- Это работающий **MVP, а не готовый продукт App Store**; для продакшена нужны авторизация, хранение данных, rate limiting, TURN, push, согласия и проверка на реальных устройствах.

## Техническая схема

- `server.js` — встроенный HTTP-сервер, комнаты, игры, сигнализация звонков, сообщения и задачи.
- `ws-lite.js` — компактный сервер WebSocket на Node.js без внешних пакетов.
- `data/rooms.json` — автоматически создаваемое локальное хранилище (не публикуй его в GitHub).
- `public/index.html`, `public/styles.css`, `public/app.js` — интерфейс на HTML/CSS/JS.
- `public/manifest.json`, `public/sw.js` — PWA.
- `mobile/` — необязательная Expo-обёртка с нативной тактильной отдачей.

## Безопасность

Пользователь явно принимает звонок и отдельно разрешает микрофон. Микрофон выключается при завершении звонка. Текст сообщений не публикуется вне комнаты. Поскольку это прототип без авторизации, не используйте его для секретной переписки до внедрения полноценной защиты.

## Запуск на своём сервере через Docker (Raspberry Pi, VPS)

В Linux с Docker и плагином Compose в корневой папке проекта:

```bash
docker compose up -d --build
docker compose ps
curl -f http://127.0.0.1:3000/health
```

В `compose.yaml` по умолчанию порт привязан к `127.0.0.1`: это сознательно, чтобы не открывать незащищённую HTTP-версию всему интернету. Для двух телефонов извне установи HTTPS reverse proxy (Caddy или Nginx), который проксирует на `127.0.0.1:3000` и поддерживает WebSocket Upgrade; настрой домен с TLS. Не добавляй открытый HTTP-сайт для микрофона. Состояние хранится в Docker volume `pulse-data` и переживает перезапуски/обновления.

Для локальной сети без reverse proxy можно изменить `PULSE_BIND=0.0.0.0`, но **микрофон в браузерах телефонов по небезопасному HTTP может не работать**. Для удалённого доступа всегда используй HTTPS.

### Публикация кода в ОТДЕЛЬНЫЙ репозиторий GitHub

1. На GitHub создай **новый пустой** репозиторий `pulse-two` (НЕ выбирай «Add a README», `.gitignore`, лицензию, чтобы не получить конфликт коммитов).
2. Скопируй адрес репозитория `https://github.com/ТВОЙ_АККАУНТ/pulse-two.git`.
3. В корне проекта выполни команды:

```bash
git init
git branch -M main
git add .
git commit -m "Initial working PULSE TWO app"
git remote add origin https://github.com/ТВОЙ_АККАУНТ/pulse-two.git
git push -u origin main
```

Чтобы запушить от имени ChatGPT без терминала, потребуется разрешить GitHub-подключению доступ к **новому репозиторию** в GitHub App settings и попросить загрузить файлы. Настроенный GitHub Actions автоматически запустит тесты после публикации.

> GitHub Pages не запустит сервер WebSocket. GitHub хранит код, а для работы приложения нужен отдельный Node.js-хостинг с HTTPS.
